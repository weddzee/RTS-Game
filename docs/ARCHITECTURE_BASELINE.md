## 1. Component responsibilities

| Directory    | Responsibility                                                                                                                                                                                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/client` | Rendering (WebGL via custom `render/gl` passes, no Pixi in this snapshot — see §3), UI (Lit web components + Tailwind 4), input/camera, WebSocket transport, lobby/matchmaking UI, replay viewer, sound (Howler). Entry: `src/client/Main.ts`.                                                                                   |
| `src/core`   | Deterministic simulation. Pure TypeScript + `zod`/`jose-base64url`/`nanoid` only (no Node built-ins, no I/O). Owns game state, intents/executions, tick, PRNG, map model, schemas + `zbin` wire codec. Runs in a Web Worker (`src/core/worker/`). All `src/core` changes require tests.                                          |
| `src/server` | Coordination + intent relay. Node.js + Express + `ws`. No simulation, no DB. In-memory `GameManager` → `GameServer` per match; `Master` (primary) + `Worker` (per-process HTTP/WS) via `cluster`. Lobby registry, turn bundling (100 ms), validation, archiving to closed API. Entry: `src/server/Server.ts`.                    |
| `resources`  | Open assets, CC BY-SA 4.0: `maps/` (132 maps, `.bin` + manifest), `sprites/`, `sounds/`, `lang/` (`en.json` source of truth), `flags/` (1082 SVGs), `images/`, `icons/`, `atlases/`, `fonts/`, `public/` (served at site root).                                                                                                  |
| `tests`      | Vitest suites: root `*.test.ts` (~150), `tests/client/` (~175), `tests/server/` (79), `tests/core/*/`, `tests/zbin/*/`, `tests/{economy,nukes,pathfinding,perf,replay,matchmaking}/`. Helper `tests/util/Setup.ts:setup()` builds a full game from `tests/testdata/maps/`. `npm test` = `vitest run && vitest run tests/server`. |
| `zbin`       | Compact binary wire format for Zod schemas. Zod stays source of truth; `zb.*` returns real Zod schema + side-table codec. Positional, no version byte — same-build only. `zbin/zb.ts`, `bytes.ts`, `context.ts`; consumers `src/core/Schemas.ts`, `src/core/ZbinWire.ts`. Golden vectors in `tests/zbin/golden.test.ts`.         |

Fourth component (not in repo): closed-source Cloudflare Worker API —
auth, stats, cosmetics, monetization, game-record storage
(`https://api.openfront.io`, dev `http://localhost:8787`).

## 3. Flow diagram (as-built)

The prompt's conceptual diagram assumes an authoritative match server
running the sim. The actual baseline is **client-simulated, server-relayed**:

```
Browser Client (Main.ts → ClientGameRunner → Transport WS)
  → Intent (Zod + zbin binary frame)
  → Authoritative match relay (Node GameServer: authorize, bundle per 100 ms Turn)
  → Turn broadcast to all clients
  → Deterministic simulation (each client: Worker.worker.ts → GameRunner → Executions → GameImpl.executeNextTick)
  → State deltas (GameUpdates → GameView)
  → Browser renderer (WebGL passes + Lit/Tailwind HUD)
```

Desync detection: clients report per-turn hashes; `DesyncDetector`
majority-votes every 10 turns and disfranchises diverged clients'
winner/liveStats votes. Replays persist `Turn[]` (`LocalServer`,
`ReplayViewer`, `VersionedReplay`).

Static assets: game server serves only `index.html` + WS; JS/CSS, maps,
worker, images come from CDN (`CDN_BASE`, empty = same-origin in dev).

## 4. GameCore separation (Prompt 0.6 invariant)

- `src/core` never imports `fs/path/http/cluster/ws/express/winston/dotenv`.
  (Minor impurity: `zod`, `jose/base64url`, `dompurify`, `nanoid` in
  `Util.ts`/`Schemas.ts` — all Workers-compatible pure TS/WebCrypto, but
  the "zero deps" claim in `CLAUDE.md` is already stale. Enforce as
  _no Node built-ins, no I/O, deterministic_ rather than _zero imports_.)
- Target shape stays valid:
  `GameCore` (`src/core`: `GameRunner` + `GameImpl` + executions)
  used by `Local/NodeMatchHost` (today: `GameServer` relay +
  client-side `GameRunner`)
  and later `CloudflareDurableObjectMatchHost` (DO per `gameID` owning
  turn log + alarm-driven `endTurn`, `WebSocketPair` hibernation).
- Rule for all future work: no Cloudflare APIs in `src/core`; keep
  `Intent → Turn → Execution → GameUpdates` pure and host-agnostic.
